Today

Do the same for any method: plant the answer, run the method, compare. Then see what messy data does to it.

Social media data adds one more problem: the rows are not independent. That is most of today.

CACTUS Fall 2026 · Week 7

Known-answer tests

Simulate, run, compare

effect = 0.5 # you choose the truth
d = simulate(effect) # make data with that truth planted
est = fit(d) # run the method you plan to use
print(est, "vs", effect) # compare: how close, and how often?

Run it once and you see one result. Run it 100 times and you see how often the method gets it right, and how far off it can be.

CACTUS Fall 2026 · Week 7

The limits

What it cannot tell you

What it shows

The method works when the data behave the way you simulated.

What it hides

Real data has bots, repeats, groups, and small samples that you did not plant.

What to do

Plant the mess on purpose, one problem at a time, and watch the answer move.

A method that passes a clean test and fails a messy one is telling you where your real data will hurt.

CACTUS Fall 2026 · Week 7

The fix

Standard errors that notice groups

Naive

Every comment is one independent row. Looks very certain, and is too certain for anything the post decides.

Clustered

Comments under a post count as one cluster. The estimate does not change. The uncertainty gets honest.

Mixed model

A model with a bump for each post. One line of code, the same idea.

Which variables are hurt most? The ones that belong to the post. A variable that changes from comment to comment is fine.

CACTUS Fall 2026 · Week 7

A check that always works

Permutation: what chance looks like

1. Shuffle

Mix up the labels so any pattern is down to chance.

2. Recompute

Calculate your statistic on the shuffled data. Do it 1,000 times.

3. Compare

Where does your real number fall among the chance numbers?

Shuffle at the level the label belongs to. A label that belongs to a post is shuffled across posts, not across comments. It works when there is no formula, such as a network statistic.
